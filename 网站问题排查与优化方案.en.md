# Website Troubleshooting and Optimization Plan

This document preserves the pre-implementation investigation results and plan; the user has reviewed and authorized implementation, and the current implementation and validation results are subject to the project code and documentation.

## 1. Requirements and Scope

- Fix the sidebar navigation errors and homepage layout issues on the Chinese and English websites.
- All resources required for the website to run, including fonts, formula rendering, Mermaid, scripts, styles, and images, are provided by the website itself and do not rely on external CDNs, third-party fonts, or remote rendering services.
- Here, “local deployment” means that the resources required when a browser accesses the site are provided from the same origin as the site; it does not mean that the website can still be opened for the first time after the user's device is completely offline, nor does it require dependency installation and GitHub Pages deployment to be completed without network access.
- The GitHub, QQ, Telegram, etc. links on the About page are external links that users click voluntarily and are not resources required for the page to run. It is recommended to keep them; clicking them naturally requires access to the corresponding external services.

## 2. Issues and Validation Results

### 1. Duplicate sidebar navigation paths cause 404 errors

**Status: reported by the user; root cause confirmed in the source code.**

- The English sidebar configures a `base` for each section in `docs/.vitepress/en-us.ts:12-15`, while the sidebar items after line 33 already use full paths such as `/About/`.
- The installed VitePress prepends `base` to sidebar links, and nested items inherit that prefix. Thus `/About/` and `/About/` become `/About/About/`, rather than the actual About page.
- The same pattern occurs in `docs/.vitepress/zh-cn.ts:13-16`; Projects, Blogs, and their nested items are affected as well. The top navigation does not use this sidebar concatenation logic.

**Recommendation:** Keep the existing full site-relative paths and remove the duplicate sidebar `base` values in both languages. Check every About, Projects, Blogs, category, and article sidebar link, including the Chinese paths; test clicks, refreshes, and browser back/forward, not just About.

### 2. Homepage cards have no layout styles

**Status: Confirmed by both the user's screenshot and the browser's computed styles.**

- `docs/index.md:22-26` and `docs/zh-cn/index.md:22-26` use classes such as `home-feature-grid` and `home-feature-card`, but the site has no corresponding styles.
- A local preview check shows that the container is a plain `block`, and the card link is `inline`, so the title, description, and link text are crowded together, matching the screenshot.

**Recommendation:** Prefer VitePress's native homepage `features`, retaining the three cards and their destinations in both languages without maintaining custom CSS. If the native component cannot meet the reviewed design requirements, consider custom styles. Check desktop and mobile widths, light and dark themes, keyboard focus, and link clickability.

### 3. Local resource requirements for fonts, formulas, and Mermaid

**Status: Representative scenarios have been verified; this does not guarantee all pages and all chart types.**

- `docs/.vitepress/head.ts:10-11` uses CSP to restrict resources such as scripts, styles, fonts, and connections; `docs/.vitepress/theme/LocalMermaid.vue:17-26` dynamically imports Mermaid from a local dependency.
- A temporary copy of the site was built with a page containing inline formulas, block formulas, and a Mermaid flowchart. With non-site network requests blocked in the browser, both formulas produced MathJax SVG, the flowchart produced Mermaid SVG, and Inter loaded from a local `.woff2` file. All 39 recorded requests were same-origin, with no failed requests, console errors, or CSP violations.
- This verification covers only one local Chromium scenario and one type of Mermaid chart; it does not prove that the online deployment, all Chinese characters, all formula commands, or all chart types meet the requirements. The Mermaid component currently specifies `Arial, sans-serif`; the fallback behavior of Chinese fonts and system fonts has not been fully verified.
- The project's existing blog demo articles have no formula or Mermaid examples, while `README.md:33` and `README.zh-CN.md:33` claim to have examples; currently there is also no automated check to prevent the future introduction of external runtime resources.

**Recommendations:**
1. Keep the existing local MathJax and Mermaid setup, and do not introduce a second renderer just because of the local deployment requirement.
2. Add real Chinese and English examples covering inline formulas, block-level formulas, and Mermaid; clarify where the examples are located in the README.
3. Audit and unify the font strategy for the site and Mermaid, and verify Chinese and English display and fallback; if all actual displayed glyphs are also required to be provided by the site, choose local fonts with appropriate licenses that cover the required glyphs, and evaluate the size of Chinese fonts.
4. Add browser automation checks: use a clean session to block and record non-site requests, listen for CSP violations and console errors, and verify font loading, formulas, and chart results; cover representative scenarios including Chinese and English, light and dark modes, and at least flowcharts.
5. Check HTML, CSS, JS, font, and image references in the final build output; keep a same-origin CSP. Regular external hyperlinks are not counted as automatically loaded resources.

### 4. Bilingual structure checks misjudge code blocks

**Status: reproduced with an isolated sample.**

`scripts/check-bilingual.mjs:20-25` scans the entire text with regular expressions. Python comments beginning with `# ` inside code blocks are misidentified as Markdown headings; two samples with identical actual heading structures therefore report `headings structure differs` and exit with status code 1. Because CI runs this check before the build, false positives block releases.

**Recommendation:** Use Markdown parsing results to identify actual headings, code fences, and tables, and clarify which structures must match across languages. Add regression tests for false positives and false negatives involving code blocks, comments, and tables, while retaining checks for missing counterpart pages.

### 5. Other improvements

- **Project page content:** `docs/Projects/index.md:5-8` and its Chinese counterpart contain only empty tables and writing notes. Replace them with an empty state for visitors; the site owner should supply project facts and entries rather than fabricate them.
- **Share preview:** The `og:image` value in `docs/.vitepress/head.ts:9` is a relative path, which some social platforms may not parse correctly. Use and verify the full HTTPS URL of the image, which remains hosted by this site.
- **Image size:** `docs/public/favicon.svg` is about 461 KB and embeds a PNG; the avatar is about 346 KB. Optimize both while maintaining visual quality.
- **Build size:** The production build reports chunks larger than 500 KB before compression; the largest JS chunk measured about 662 KB. Mermaid is already imported on demand, and the current data does not show whether every page's first load is affected. Measure real page loads before changing code splitting rather than merely hiding the warning.
- **Bilingual content:** The English homepage introduction is more detailed than the Chinese one. Whether to align them is a content choice for the site owner; do not invent personal information.

## III. Recommended implementation order

1. Fix all sidebar target paths in Chinese and English.
2. Organize the homepage card layout, covering responsive and theme states.
3. Set up local asset validation and Chinese/English formula and Mermaid examples, and review the font strategy.
4. Fix false positives in the bilingual check and add regression tests.
5. Address share previews and asset size; adjust content empty states and bilingual copy according to review feedback.

## IV. Acceptance After Completion

- `pnpm check:bilingual` and `pnpm docs:build` both pass; run the corresponding regression tests for boundary conditions in the bilingual check.
- All sidebar items and nested article links for About, Projects, and Blogs in Chinese and English point to actual pages; direct opening, clicking, refreshing, and forward/back navigation all work normally.
- On the homepage, in both languages, at desktop and mobile widths, and in light and dark themes, cards are arranged independently, text does not overlap, and keyboard operation is supported.
- In browser validation of the production build, after blocking all automatic requests to non-site origins, fonts, inline/block formulas, and Mermaid on representative pages all work normally; there are no non-site resource requests, CSP violations, or console errors. Clearly record the test scope to avoid treating sampling results as proof for all syntax.
- The bilingual examples are consistent with the README; existing content and outbound active links are retained, and no third-party runtime services are introduced.
